# Дипломная работа по профессии «Системный администратор»

**Студент:** Лукьянов Михаил

## Задача

Разработать отказоустойчивую инфраструктуру для статического веб-сайта в Yandex Cloud с балансировкой нагрузки, мониторингом, сбором логов и резервным копированием.

## Архитектура

В инфраструктуре используются:

- два web-сервера nginx в разных зонах доступности;
- Application Load Balancer;
- Bastion host;
- Zabbix и Zabbix Agent 2;
- Elasticsearch, Filebeat и Kibana;
- VPC с публичными и приватными подсетями;
- Security Groups;
- NAT Gateway;
- ежедневное резервное копирование дисков.

Web-серверы и Elasticsearch размещены в приватных подсетях и не имеют публичных IP-адресов.

## Основные компоненты

### Сайт

Два идентичных nginx-сервера:

- `web-a.ru-central1.internal`
- `web-b.ru-central1.internal`

Трафик распределяется через Application Load Balancer.

Настроены Target Group, Backend Group, HTTP Router и healthcheck `/` на порту 80.

### Мониторинг

На отдельной ВМ развёрнут Zabbix Server.

Dashboard содержит метрики по принципу USE для CPU, RAM, дисков и сети, а также показатели HTTP:

- response time;
- requests per second;
- ошибки HTTP-сценария;
- CPU load average.

Настроены пороговые значения и HTTP-сценарий проверки сайта.

### Логи

Filebeat на web-серверах отправляет nginx `access.log` и `error.log` в Elasticsearch.

Kibana подключена к Elasticsearch и используется для просмотра и анализа логов.

Для Elastic-компонентов использованы официальные Docker-образы, что предусмотрено заданием при недоступности ресурсов Elastic для установки.

### Сеть и безопасность

Используется один VPC с публичными и приватными подсетями.

Административный доступ к внутренним серверам осуществляется через Bastion host.

Доступ между компонентами ограничен с помощью Security Groups.

Для исходящего доступа внутренних серверов используется NAT Gateway.

### Резервное копирование

Настроено ежедневное создание snapshots дисков всех шести виртуальных машин.

Срок хранения резервных копий — 7 дней.

Перед сдачей все виртуальные машины переведены в постоянный режим работы.

## Автоматизация

Инфраструктура создаётся с помощью Terraform.

Настройка серверов выполняется с помощью Ansible, запущенного на Bastion host.

Ansible inventory использует FQDN виртуальных машин в зоне `.ru-central1.internal`, без IP-адресов.

## Проверка

Работоспособность инфраструктуры подтверждена:

- доступностью сайта через Application Load Balancer;
- работой обоих web-серверов;
- получением метрик в Zabbix;
- работой HTTP-сценария;
- поступлением nginx-логов в Elasticsearch;
- отображением логов в Kibana;
- настроенным резервным копированием.

Подтверждающие скриншоты находятся в каталоге `screenshots`.

## Безопасность

Секретные данные не публикуются в Git-репозитории.

В `.gitignore` исключены:

- `terraform.tfvars`;
- файлы состояния Terraform;
- каталог `.terraform`;
- файлы ключей;
- JSON-файлы.

Локальный ключ сервисного аккаунта Yandex Cloud не включён в репозиторий.

## Решения и компромиссы

Для виртуальных машин использованы минимальные конфигурации, предусмотренные заданием: 2 vCPU, ограничение CPU 20%, 2–4 ГБ RAM и 10 ГБ диска.

Ansible размещён непосредственно на Bastion host, поскольку такой вариант допускается условиями дипломного задания.

Для Elasticsearch, Kibana и Filebeat использованы официальные Docker-образы Elastic в соответствии с рекомендацией задания на случай недоступности ресурсов Elastic для скачивания.

Дополнительные возможности из раздела «Дополнительно» в текущей реализации не используются. Основное внимание уделено выполнению минимальных требований дипломной работы.
